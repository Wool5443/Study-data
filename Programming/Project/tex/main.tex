\section*{Задание на курсовую работу}

\textbf{Тема:} реализовать программу для пакетной конвертации видеороликов в более эффективный формат для сокращения занимаемого места на диске.

\textbf{Цель работы:} разработать настольное приложение Floppy, позволяющее пользователю выбрать один или несколько видеофайлов и перекодировать их в формат HEVC с настройкой качества, разрешения и частоты кадров. Итоговая программа должна уменьшать размер видеофайлов при сохранении приемлемого качества изображения.

\textbf{Задачи работы:}

\begin{enumerate}
	\item
	      изучить предметную область хранения и перекодирования видеороликов;
	\item
	      рассмотреть существующие инструменты и подходы к сжатию видео;
	\item
	      выбрать технологический стек для реализации настольного приложения;
	\item
	      реализовать пользовательский интерфейс для выбора файлов и настройки параметров перекодирования;
	\item
	      реализовать модуль перекодирования через FFmpeg;
	\item
	      добавить пакетную обработку файлов и отображение прогресса;
	\item
	      провести тестирование основных сценариев работы программы;
	\item
	      подготовить пользовательскую и разработческую документацию.
\end{enumerate}

\textbf{Функциональные требования:}

\begin{enumerate}
	\item
	      программа должна позволять выбрать один или несколько видеофайлов через диалог выбора файлов;
	\item
	      программа должна поддерживать добавление файлов перетаскиванием в окно приложения;
	\item
	      программа должна принимать на вход локальные видеофайлы, доступные файловой системе пользователя;

	\item
	      программа должна позволять ограничить высоту выходного видео;
	\item
	      программа должна позволять ограничить частоту кадров выходного видео;
	\item

\section{Введение}

Объем видеоданных, которые пользователи хранят на персональных компьютерах и внешних накопителях, постоянно увеличивается. Видеоролики с мобильных устройств, камер и экранных записей часто сохраняются в высоком разрешении и занимают значительное место на диске. При этом часть таких файлов используется только для архива, пересылки или просмотра, поэтому для них важнее рациональный размер, чем слишком высокое качество.

Одним из способов уменьшения размера видео является перекодирование в более эффективный видеокодек. В данной работе используется формат HEVC, также известный как H.265. Он позволяет добиться более высокой степени сжатия по сравнению с рядом старых форматов при сопоставимом визуальном качестве [1]. Для практической обработки видео выбран FFmpeg, так как он является стандартом в индустрии для кодирования, декодирования и преобразования мультимедийных файлов [2].

Актуальность темы связана с тем, что работа с FFmpeg требует специфических знаний об устройстве кодеков и о возможностях разных аппартных ускорителей. Итого, прежде чем понять, как на конкретном компьютере пользоваться FFmpeg, нужно довольно глубоко погрузиться в документацию этой утилиты. Поэтому целесообразно разработать графическое приложение, которое скрывает низкоуровневые команды и предоставляет понятные элементы управления.

Целью курсовой работы является разработка приложения Floppy для пакетной конвертации видеороликов в эффективный формат хранения. Для достижения цели необходимо решить следующие задачи:

\begin{itemize}
	\item
	      определить требования к приложению;
	\item
	      изучить инструменты перекодирования видео;
	\item
	      реализовать выбор файлов и параметров обработки;
	\item
	      реализовать запуск FFmpeg из Python-приложения;
	\item
	      обеспечить отображение прогресса и сообщений о результате;
	\item
	      провести тестирование основных пользовательских сценариев.
\end{itemize}

\section{Обзор аналогов и источников}

Для решения задачи уменьшения размера видео существуют как универсальные консольные инструменты, так и графические приложения.

FFmpeg является наиболее гибким инструментом. Он поддерживает большое количество контейнеров, кодеков, фильтров и аппаратных кодировщиков [2]. Его преимуществом является высокая универсальность, а недостатком для рядового пользователя является сложность командной строки.

HandBrake является популярным графическим приложением для перекодирования видео. Оно предоставляет готовые профили, настройки качества и очереди задач. Сильной стороной такого подхода является развитый интерфейс, но для учебного проекта избыточность HandBrake показывает, что можно реализовать более простое приложение, ориентированное только на пакетное сжатие выбранных файлов.

Для реализации интерфейса Floppy используется GTK~4 через PyGObject. GTK предоставляет виджеты для окон, кнопок, полей ввода, диалогов выбора файлов и индикаторов прогресса [3]. Для асинхронной работы с FFmpeg выбрана библиотека python-ffmpeg, которая позволяет запускать обработку из Python-кода и получать события прогресса [4].

В результате анализа был выбран подход, при котором графический интерфейс отвечает за взаимодействие с пользователем, а обработка видео выполняется через FFmpeg. Такой вариант позволяет не реализовывать кодирование самостоятельно, а использовать готовый и проверенный инструмент.

\section{Описание разработанного приложения}

Разработанное приложение Floppy представляет собой настольную программу с графическим интерфейсом. Оно предназначено для пакетного перекодирования видеороликов в HEVC. Пользователь выбирает один или несколько файлов, задает параметры обработки и запускает кодирование. Для каждого входного файла создается отдельный выходной файл с суффиксом \texttt{\_compressed}.

Проект состоит из следующих основных файлов:

\begin{itemize}
	\item
	      \texttt{app.py} -- модуль графического интерфейса и пользовательских сценариев;
	\item
	      \texttt{engine.py} -- модуль запуска перекодирования;
	\item
	      \texttt{utils.py} -- вспомогательный модуль для работы с FFmpeg, FFprobe и параметрами кодировщиков;
	\item
	      \texttt{requirement.txt} -- список Python-зависимостей проекта.
\end{itemize}

Пользовательский интерфейс реализован в классе \texttt{MainWindow}. Окно содержит название приложения, строку выбранных файлов, кнопку выбора файлов, подсказку о перетаскивании, поля настройки качества, разрешения и частоты кадров, индикатор прогресса, строку статуса и кнопку запуска перекодирования.

\section{Архитектура и реализация}

\subsection{Графический интерфейс}

Модуль \texttt{app.py} создает GTK-приложение с идентификатором \texttt{dev.floppy.\allowbreak Reencoder}. При активации приложения создается главное окно. В интерфейсе используется вертикальное расположение элементов: сверху находится заголовок, далее идут элементы выбора файлов и настройки параметров, затем индикатор прогресса и кнопка запуска.

Выбор файлов реализован через \texttt{Gtk.FileChooserNative}. Диалог поддерживает множественный выбор. Дополнительно в окно добавлен обработчик перетаскивания файлов через \texttt{Gtk.DropTarget}. Это позволяет пользователю выбрать видео как через стандартный диалог, так и прямым переносом файлов в окно.

Для настройки качества используется числовое поле со значениями от 1 до 51. Разрешение и частота кадров также задаются числовыми полями. Значение 0 для разрешения означает сохранение исходного размера кадра, а значение 0 для частоты кадров означает сохранение исходной частоты кадров.

\subsection{Пакетная обработка}

После нажатия кнопки \texttt{Reencode} приложение проверяет, выбраны ли файлы. Если список пуст, пользователь получает сообщение \texttt{Choose files first}. Если файлы выбраны, интерфейс блокирует кнопки выбора и запуска, чтобы пользователь не начал вторую обработку параллельно.

Перекодирование выполняется в отдельном потоке. Это важно для графического интерфейса: длительная операция FFmpeg не должна блокировать основной поток GTK. После обработки каждого файла статус обновляется, а прогресс устанавливается в 100 процентов. При возникновении ошибки приложение разблокирует кнопки и показывает сообщение с количеством уже обработанных файлов.

\subsection{Модуль перекодирования}

Модуль \texttt{engine.py} содержит асинхронную функцию \texttt{reencode}. Она принимает путь к входному файлу, параметр качества, ограничение разрешения, ограничение частоты кадров и необязательную функцию обратного вызова для прогресса.

Перед запуском FFmpeg модуль определяет исходное разрешение и частоту кадров. Если пользовательское ограничение выше или равно исходному значению, параметр не применяется. Это предотвращает бессмысленное увеличение разрешения или частоты кадров при сжатии.

Имя выходного файла формируется на основе имени входного файла. К исходному имени добавляется суффикс \texttt{\_compressed}, расширение сохраняется. Далее создается объект \texttt{FFmpeg}, указываются входной файл, выходной файл и рассчитанные параметры кодирования.

\subsection{Выбор кодировщика}

Модуль \texttt{utils.py} отвечает за выбор доступного HEVC-кодировщика. В проекте описаны варианты \texttt{hevc\_nvenc}, \texttt{hevc\_qsv}, \texttt{hevc\_vaapi}, \texttt{hevc\_amf}, \texttt{hevc\_vulkan} и \texttt{libx265}. Сначала программа получает список доступных кодировщиков FFmpeg, затем проверяет их в порядке приоритета.

Если доступен аппаратный кодировщик, приложение может использовать его. Если подходящий аппаратный вариант не найден, используется программный \texttt{libx265}. Для каждого кодировщика заданы собственные параметры качества, так как разные реализации FFmpeg используют разные имена опций.

Такой подход делает приложение более переносимым между компьютерами с разными видеокартами и конфигурациями FFmpeg. При этом пользователю не нужно вручную выбирать конкретный кодировщик.

\section{Ход разработки}

Разработка проекта выполнялась поэтапно. На первом этапе была сформулирована задача: создать программу для пакетной конвертации видеороликов в более эффективный формат. Был выбран стек Python и FFmpeg, так как Python подходит для быстрой разработки пользовательского приложения, а FFmpeg предоставляет готовые средства обработки видео.

На втором этапе был реализован базовый модуль перекодирования. Он запускал FFmpeg для одного файла, формировал выходное имя и применял параметр качества. После этого была добавлена работа с FFprobe для получения данных о видео: количества кадров, разрешения и частоты кадров.

На третьем этапе была добавлена логика выбора кодировщика. Приложение стало проверять доступные HEVC-кодировщики и выбирать наиболее подходящий вариант. Это позволило поддержать как аппаратное, так и программное кодирование.

На четвертом этапе был разработан графический интерфейс на GTK~4. В него были добавлены выбор файлов, поля настройки качества, разрешения и частоты кадров, строка статуса и индикатор прогресса.

На пятом этапе была реализована пакетная обработка. Пользователь получил возможность выбрать несколько файлов, после чего приложение обрабатывает их последовательно и показывает количество завершенных операций.

\section{Заключение}

В ходе курсовой работы было разработано настольное приложение Floppy для пакетной конвертации видеороликов в эффективный формат хранения. Программа реализована на языке Python с использованием GTK~4 для графического интерфейса и FFmpeg для обработки видео.

В приложении реализованы выбор одного или нескольких файлов, добавление файлов перетаскиванием, настройка качества, ограничение разрешения и частоты кадров, последовательное перекодирование файлов, отображение прогресса и сообщений о результате. Для повышения переносимости реализован автоматический выбор доступного HEVC-кодировщика.

Разработанное приложение решает поставленную задачу: позволяет уменьшать размер видеофайлов без ручного ввода команд FFmpeg. В качестве дальнейшего развития можно добавить сохранение пользовательских настроек, журнал выполненных операций, предварительную оценку размера результата и более подробные сообщения об ошибках.

\subsection{Назначение программы}

Floppy предназначено для пакетного перекодирования видеороликов в HEVC. Программа помогает уменьшить размер видеофайлов на диске и не требует от пользователя ручного ввода команд FFmpeg.

\subsection{Установка}

Для работы приложения требуется Linux, Python, GTK~4, FFmpeg и Python-зависимости из файла \texttt{requirement.txt}. Перед запуском необходимо установить системные пакеты GTK~4 и FFmpeg средствами пакетного менеджера операционной системы, затем установить зависимости Python.

Пример установки Python-зависимостей:

\begin{verbatim}
pip install -r requirement.txt
\end{verbatim}

\subsection{Запуск}

Запуск приложения выполняется из каталога проекта:

\begin{verbatim}
python app.py
\end{verbatim}

После запуска открывается окно Floppy с элементами выбора файлов и настройки параметров.

\subsection{Типовые ошибки}

Если пользователь нажал \texttt{Reencode}, но не выбрал файлы, программа выводит сообщение \texttt{Choose files first}. Нужно выбрать хотя бы один видеофайл и повторить запуск.

Если в системе не установлен FFmpeg или отсутствует подходящий HEVC-кодировщик, перекодирование завершится ошибкой. В этом случае нужно установить FFmpeg или включить кодировщик HEVC в используемой сборке FFmpeg.

Если выбранный файл поврежден или не является видеофайлом, FFmpeg может завершить обработку с ошибкой. Нужно проверить исходный файл или выбрать другой файл.

\section{Руководство разработчика}

\subsection{Структура проекта}

Проект Floppy расположен в каталоге \texttt{floppy}. Основные файлы:

\begin{itemize}
	\item
	      \texttt{app.py} -- точка входа приложения и описание графического интерфейса;
	\item
	      \texttt{engine.py} -- логика перекодирования одного файла;
	\item
	      \texttt{utils.py} -- работа с FFmpeg, FFprobe, кодировщиками и параметрами вывода;
	\item
	      \texttt{requirement.txt} -- список Python-зависимостей.
\end{itemize}

\subsection{Поток выполнения}

При запуске \texttt{app.py} создается объект \texttt{FloppyApp}, затем главное окно \texttt{MainWindow}. Пользователь выбирает файлы, после чего метод обработки кнопки считывает значения интерфейса и запускает отдельный поток. В этом потоке для каждого файла вызывается асинхронная функция \texttt{engine.reencode}.

Функция \texttt{reencode} получает технические данные исходного видео через функции из \texttt{utils.py}, формирует параметры FFmpeg и запускает обработку. Прогресс передается обратно в интерфейс через callback. Обновление GTK-виджетов выполняется через \texttt{GLib.idle\_add}, чтобы изменения происходили в основном потоке интерфейса.

\subsection{Выбор кодировщика}

Доступные кодировщики описаны в словаре \texttt{ENCODERS}. Порядок выбора задан списком \texttt{ENCODER\_PRIORITIES}. Для добавления нового кодировщика нужно:

\begin{itemize}
	\item
	      добавить описание в \texttt{ENCODERS};
	\item
	      указать имя кодека FFmpeg;
	\item
	      задать параметры качества;
	\item
	      при необходимости указать аппаратное ускорение и дополнительные параметры;
	\item
	      добавить ключ кодировщика в \texttt{ENCODER\_PRIORITIES}.
\end{itemize}

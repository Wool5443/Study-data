\section*{Задание на курсовую работу}

\textbf{Тема:} разработка программы для пакетного преобразования видеозаписей в более компактный формат, позволяющий уменьшить объем занимаемого места на носителе.

\textbf{Цель работы:} разработать приложение, с помощью которого пользователь сможет выбрать один или несколько видеофайлов и перекодировать их, задав параметры качества, разрешения и частоты кадров, чтобы уменьшить их размер.

\textbf{Задачи работы:}
\begin{enumerate}
	\item изучить предметную область хранения и преобразования видеофайлов;
	\item рассмотреть существующие средства и методы сжатия видео;
	\item выбрать технологический стек для разработки десктопного приложения;
	\item реализовать графический интерфейс для выбора файлов и настройки параметров перекодирования;
	\item реализовать модуль перекодирования с использованием FFmpeg;
	\item добавить пакетную обработку файлов и отображение хода выполнения;
	\item протестировать приложение;
	\item подготовить пользовательскую и разработческую документацию.
\end{enumerate}

\textbf{Функциональные требования:}
\begin{enumerate}
	\item программа должна позволять выбирать один или несколько видеофайлов через стандартный диалог выбора файлов;
	\item программа должна поддерживать добавление файлов перетаскиванием в окно приложения;
	\item программа должна позволять задавать параметр качества перекодирования;
	\item программа должна позволять ограничивать высоту выходного видео;
	\item программа должна позволять ограничивать частоту кадров выходного видео;
	\item программа должна создавать выходные файлы с суффиксом \texttt{\_compressed};
	\item программа должна позволять копировать метаданные исходного файла в результат;
	\item программа должна отображать прогресс выполнения операции;
	\item программа должна сообщать пользователю об ошибке, если перекодирование завершилось неуспешно.
\end{enumerate}

\textbf{Нефункциональные требования:}
\begin{enumerate}
	\item язык реализации: Python;
	\item графический интерфейс: GTK~4 через PyGObject;
	\item обработка видео: FFmpeg и библиотека python-ffmpeg;
	\item копирование метаданных: FFmpeg и ExifTool;
	\item платформа: десктопная операционная система Linux с установленными FFmpeg и GTK~4;
	\item формат хранения данных: локальные файлы пользователя, без использования базы данных.
\end{enumerate}

\textbf{Ожидаемые результаты:}
\begin{enumerate}
	\item рабочее приложение для пакетного перекодирования видео;
	\item исходный код проекта;
	\item инструкция по запуску и использованию;
	\item примеры входных данных и результата перекодирования.
\end{enumerate}

\section*{Аннотация}

В курсовой работе рассматривается разработка десктопного приложения Floppy для пакетной конвертации видеороликов в формат HEVC. Объектом разработки является программное средство, предназначенное для уменьшения объема, занимаемого видеофайлами на диске. Цель работы состоит в создании приложения с графическим интерфейсом, которое позволяет выбрать несколько видеофайлов, настроить качество, разрешение и частоту кадров, а затем выполнить перекодирование для экономии места на носителе.

В ходе работы были рассмотрены основные подходы к сжатию видео, выбран стек Python, GTK~4, PyGObject, FFmpeg, ExifTool и python-ffmpeg. В приложении реализованы модули пользовательского интерфейса, выбора параметров, определения доступного HEVC-кодировщика, запуска FFmpeg, копирования метаданных и отображения прогресса. В результате была создана программа для локальной обработки видеофайлов без использования сетевых сервисов и базы данных.

Работа содержит 20 страниц, 1 иллюстрацию, 1 таблицу, 8 использованных источников.

This coursework examines the development of a desktop application called Floppy for batch converting video clips to HEVC format. The focus of the project is a software tool designed to reduce the disk space occupied by video files. The aim of the project is to create an application with a graphical user interface that allows the user to select multiple video files, configure the quality, resolution and frame rate, and then perform transcoding to save storage space.

During the project, the main approaches to video compression were examined, and the following stack was selected: Python, GTK~4, PyGObject, FFmpeg, ExifTool and python-ffmpeg. The application implements modules for the user interface, parameter selection, detection of an available HEVC encoder, launching FFmpeg, copying metadata and displaying progress. The result is a programme for local processing of video files without the use of network services or a database.

\section{Введение}

Видеофайлы, снятые на мобильные устройства, камеры или полученные в результате записи экрана, часто занимают значительный объем дискового пространства. Это особенно заметно при хранении архивов, пересылке файлов или накоплении большого количества коротких роликов. Если видео не планируется использовать для дальнейшего монтажа, его можно перекодировать с другими параметрами качества, разрешения и частоты кадров, тем самым уменьшив размер файла.

Один из распространенных способов уменьшения размера видео заключается в переходе на более эффективный видеокодек. В данной работе используется HEVC, также известный как H.265. В описании рекомендации ITU-T указано, что стандарт был разработан в ответ на потребность в более высоком сжатии движущихся изображений~\cite{h265}. Для обработки видео выбран FFmpeg. Его документация описывает инструмент как универсальный медиаконвертер, который может читать различные входные данные, фильтровать и транскодировать их в разные выходные форматы~\cite{ffmpeg}.

Актуальность темы связана с тем, что работа с FFmpeg через командную строку требует от пользователя знания кодеков, параметров качества, фильтров и правил формирования выходных файлов. В приложении Floppy эти действия перенесены в графический интерфейс. Пользователь задает параметры через элементы управления, а приложение самостоятельно формирует команду и выбирает доступный HEVC-кодировщик.

Целью курсовой работы является разработка приложения Floppy для пакетной конвертации видеороликов в эффективный формат хранения. Для достижения этой цели необходимо решить следующие задачи:

\begin{itemize}
	\item определить требования к приложению;
	\item изучить инструменты перекодирования видео;
	\item реализовать запуск FFmpeg из Python-приложения;
	\item реализовать выбор файлов и параметров обработки;
	\item обеспечить отображение прогресса и сообщений о результате;
	\item провести тестирование основных пользовательских сценариев.
\end{itemize}

\section{Обзор аналогов и источников}

Для уменьшения размера видео можно использовать как консольные инструменты, так и готовые графические приложения. В рамках данной работы были рассмотрены решения, которые позволяют выполнять перекодирование видео и настраивать параметры результата.

В качестве базового инструмента обработки видео выбран FFmpeg. Его документация описывает поддержку входных файлов, фильтрации и транскодирования в выходные форматы~\cite{ffmpeg}. Для приложения Floppy это важно, поскольку собственная реализация видеокодека не требуется: программа только формирует параметры обработки и запускает FFmpeg.

В качестве графического аналога рассмотрен HandBrake. Документация HandBrake описывает готовые профили настроек для устройств и типовых сценариев, а также аппаратные профили для кодирования через специализированные медиаблоки современных видеоустройств~\cite{handbrake}. В HandBrake также есть функция \textit{Passthru common Metadata}, однако документация описывает ее как перенос ограниченного набора распространенных полей метаданных~\cite{handbrakemetadata}. В Floppy выбран другой сценарий: при включении \texttt{Copy metadata} приложение сначала копирует метаданные и главы средствами FFmpeg, а затем переносит теги через ExifTool с сохранением групп тегов~\cite{ffmpegmetadata,exiftool}.

Графический интерфейс Floppy реализован на GTK~4 через PyGObject. GTK предоставляет необходимые виджеты для окон, кнопок, полей ввода, диалогов выбора файлов и индикаторов прогресса~\cite{pygobject}. Для асинхронного запуска FFmpeg из Python выбрана библиотека python-ffmpeg, которая позволяет управлять обработкой из кода и получать события прогресса~\cite{pythonffmpeg}.

По итогам анализа был выбран подход, при котором пользователь взаимодействует с графическим интерфейсом, а вся обработка видео выполняется через FFmpeg. Такой вариант соответствует задаче курсовой работы: разработать удобную оболочку для пакетного перекодирования без самостоятельной реализации алгоритмов видеосжатия.

\section{Описание разработанного приложения}

Разработанное приложение Floppy представляет собой десктопную программу с графическим интерфейсом. Оно предназначено для пакетного перекодирования видеороликов в HEVC. Пользователь выбирает один или несколько файлов, задает параметры обработки и запускает кодирование. Для каждого входного файла рядом с ним создается отдельный выходной файл с суффиксом \texttt{\_compressed}.

Проект состоит из следующих основных файлов:

\begin{itemize}
	\item \texttt{app.py} --- модуль графического интерфейса и пользовательских сценариев;
	\item \texttt{engine.py} --- модуль запуска перекодирования;
	\item \texttt{utils.py} --- вспомогательный модуль для работы с FFmpeg, FFprobe и параметрами кодировщиков;
	\item \texttt{requirements.txt} --- список Python-зависимостей проекта.
\end{itemize}

Пользовательский интерфейс реализован в классе \texttt{MainWindow}. Главное окно содержит название приложения, строку с выбранными файлами, кнопку выбора файлов, подсказку о поддержке перетаскивания, поля настройки качества, разрешения и частоты кадров, переключатель копирования метаданных, индикатор прогресса, строку статуса и кнопку запуска перекодирования.

\section{Архитектура и реализация}

\subsection{Графический интерфейс}

Модуль \texttt{app.py} создает GTK-приложение с идентификатором \texttt{dev.floppy.\allowbreak Reencoder}. При активации приложения создается главное окно. Элементы интерфейса расположены вертикально: в верхней части находится заголовок, ниже размещены элементы выбора файлов и настройки параметров, затем индикатор прогресса и кнопка запуска.

Выбор файлов реализован через \texttt{Gtk.FileChooserNative}. Диалог поддерживает множественный выбор, поэтому пользователь может сразу добавить несколько видеофайлов. Кроме того, в окно добавлен обработчик перетаскивания файлов через \texttt{Gtk.DropTarget}. Благодаря этому файлы можно добавить как через стандартный диалог, так и простым переносом в окно приложения.

Для настройки качества используется числовое поле со значениями от 1 до 51. Разрешение и частота кадров также задаются числовыми полями. Значение 0 для разрешения означает сохранение исходного размера кадра, а значение 0 для частоты кадров --- сохранение исходной частоты. Переключатель \texttt{Copy metadata} включает перенос метаданных из исходного файла в выходной.

\subsection{Пакетная обработка}

После нажатия кнопки \texttt{Reencode} приложение проверяет, выбраны ли файлы. Если список пуст, пользователь получает сообщение \texttt{Choose files first}. Если файлы выбраны, интерфейс считывает параметры качества, разрешения, частоты кадров и состояние переключателя копирования метаданных. Затем кнопки выбора и запуска временно блокируются, чтобы пользователь не мог начать вторую обработку параллельно с уже запущенной.

Перекодирование выполняется в отдельном потоке, поэтому основной поток GTK не блокируется. Во время обработки пользователь видит полосу прогресса, название текущего файла и количество уже обработанных файлов. Если возникает ошибка, приложение останавливает обработку, разблокирует элементы управления и показывает сообщение с информацией о том, сколько файлов было успешно обработано до сбоя.

\subsection{Модуль перекодирования}

Модуль \texttt{engine.py} содержит асинхронную функцию \texttt{reencode}. Она принимает путь к входному файлу, параметр качества, ограничение разрешения, ограничение частоты кадров, признак копирования метаданных и необязательную функцию обратного вызова для обновления прогресса.

Перед запуском FFmpeg модуль определяет исходное разрешение и частоту кадров. Если пользовательское ограничение выше или равно исходному значению, соответствующий параметр не применяется. Это исключает бессмысленное увеличение разрешения или частоты кадров при задаче сжатия. Если включено копирование метаданных, модуль заранее проверяет доступность ExifTool, чтобы не запускать длительное перекодирование при отсутствии необходимой внешней утилиты.

Имя выходного файла формируется на основе имени исходного файла: к нему добавляется суффикс \texttt{\_compressed}, а расширение сохраняется. Далее создается объект \texttt{FFmpeg}, указываются входной и выходной файлы, а также рассчитанные параметры кодирования. При включенном копировании метаданных в параметры FFmpeg добавляются \texttt{map\_metadata=0} и \texttt{map\_chapters=0}. После завершения кодирования вызывается ExifTool с аргументами \texttt{-TagsFromFile}, \texttt{-all:all} и путем к выходному файлу.

\subsection{Выбор кодировщика}

Модуль \texttt{utils.py} отвечает за выбор доступного HEVC-кодировщика. В проекте описаны варианты \texttt{hevc\_nvenc}, \texttt{hevc\_qsv}, \texttt{hevc\_vaapi}, \texttt{hevc\_amf}, \texttt{hevc\_vulkan} и \texttt{libx265}. Сначала программа получает список кодировщиков, доступных в установленной сборке FFmpeg, затем проверяет их в порядке заданного приоритета.

Если найден подходящий аппаратный кодировщик, приложение может использовать его для ускорения обработки. Если аппаратный вариант недоступен, используется программный кодировщик \texttt{libx265}. Для каждого кодировщика заданы собственные параметры качества, поскольку разные реализации FFmpeg используют разные имена и смысл опций.

Такой подход делает приложение более переносимым между компьютерами с разными видеокартами и разными сборками FFmpeg. Пользователю при этом не нужно вручную выбирать конкретный кодировщик или разбираться в особенностях своей системы.

\subsection{Копирование метаданных}

Копирование метаданных реализовано как необязательный режим. Если пользователь включает \texttt{Copy metadata}, приложение выполняет две операции. Сначала FFmpeg получает параметры \texttt{map\_metadata=0} и \texttt{map\_chapters=0}, которые указывают копировать метаданные и главы из первого входного файла~\cite{ffmpegmetadata}. Затем, после успешного перекодирования, вызывается ExifTool с командой копирования тегов из исходного файла в выходной. Документация ExifTool описывает форму \texttt{-TagsFromFile src -all:all dst} как копирование тегов с сохранением исходных групп~\cite{exiftool}.

Если ExifTool недоступен, приложение завершает операцию до запуска FFmpeg и выводит понятное сообщение об ошибке. Это позволяет избежать ситуации, при которой пользователь ждет завершения перекодирования, а затем узнает, что метаданные не могут быть перенесены.

\section{Ход разработки}

Разработка проекта велась поэтапно. Сначала была сформулирована основная задача: создать программу для пакетной конвертации видеороликов в более эффективный формат хранения. Для реализации был выбран стек Python и FFmpeg. Python используется для графического приложения и связующей логики, а FFmpeg выполняет непосредственную обработку видео.

На первом этапе был реализован базовый модуль перекодирования одного файла. Он запускал FFmpeg, формировал имя выходного файла и применял параметр качества. Затем в проект была добавлена работа с FFprobe, с помощью которого приложение получает технические сведения об исходном видео: разрешение, частоту кадров и другие параметры, необходимые для корректной настройки обработки.

Следующим этапом стала реализация выбора кодировщика. Приложение проверяет доступные HEVC-кодировщики и выбирает подходящий вариант из заданного списка приоритетов. Это позволяет использовать аппаратное кодирование там, где оно доступно, и переходить на программное кодирование через \texttt{libx265}, если аппаратный кодировщик отсутствует.

После этого был разработан графический интерфейс на GTK~4. В него были добавлены выбор файлов, настройки качества, разрешения и частоты кадров, а также индикатор прогресса. Затем была реализована обработка нескольких файлов и добавление файлов перетаскиванием. На заключительном этапе в приложение был добавлен режим копирования метаданных.

\section{Тестирование}

Для проверки приложения были выделены основные контрольные сценарии, связанные с функциональными требованиями.
\begin{enumerate}
	\item \textbf{Запуск приложения.} Программа должна открыть главное окно, отобразить элементы управления и не завершиться с ошибкой при наличии необходимых зависимостей.
	\item \textbf{Выбор одного файла.} После выбора одного видео в интерфейсе должно отображаться имя файла, а кнопка запуска должна начинать обработку.
	\item \textbf{Выбор нескольких файлов.} После выбора нескольких файлов приложение должно отображать их количество и последовательно обрабатывать список.
	\item \textbf{Перетаскивание файлов.} Файлы должны добавляться переносом в окно приложения.
	\item \textbf{Настройка качества.} Указанное пользователем значение качества должно передаваться в параметры выбранного кодировщика.
	\item \textbf{Ограничение разрешения.} При значении 0 должен сохраняться исходный размер кадра, а при меньшем значении должен применяться фильтр масштабирования.
	\item \textbf{Ограничение частоты кадров.} При значении 0 должна сохраняться исходная частота кадров, а при меньшем значении должен применяться фильтр \texttt{fps}.
	\item \textbf{Копирование метаданных.} При включенном переключателе \texttt{Copy metadata} должны добавляться параметры копирования метаданных FFmpeg и выполняться перенос тегов через ExifTool.
	\item \textbf{Обработка ошибки.} При ошибке FFmpeg приложение должно разблокировать кнопки и вывести сообщение о сбое.
\end{enumerate}

Эти сценарии покрывают основные функции, указанные в техническом задании: выбор файлов, настройку параметров, запуск перекодирования, копирование метаданных, отображение прогресса, обработку ошибок и сохранение результата в файл с суффиксом \texttt{\_compressed}.

\section{Заключение}

В ходе курсовой работы было разработано десктопное приложение Floppy для пакетной конвертации видеороликов в эффективный формат хранения. Программа реализована на языке Python с использованием GTK~4 для графического интерфейса и FFmpeg для обработки видео.

В приложении реализованы выбор одного или нескольких файлов, добавление файлов перетаскиванием, настройка качества, ограничение разрешения и частоты кадров, копирование метаданных, последовательное перекодирование файлов, отображение прогресса и сообщений о результате. Для повышения переносимости добавлен автоматический выбор доступного HEVC-кодировщика.

Разработанное приложение решает поставленную задачу: оно позволяет уменьшать размер видеофайлов без ручного ввода команд FFmpeg. В дальнейшем проект можно развить, добавив выбор каталога для результатов, журнал выполненных операций, отмену текущей обработки и предварительную оценку ожидаемого размера выходного файла.

\subsection{Назначение программы}

Floppy предназначено для пакетного перекодирования видеороликов в HEVC. Программа помогает уменьшить размер видеофайлов на диске и не требует от пользователя ручного ввода команд FFmpeg.

\subsection{Установка}

Для работы приложения требуются Linux, Python, GTK~4, FFmpeg, ExifTool и Python-зависимости из файла \texttt{requirements.txt}. Перед запуском необходимо установить системные пакеты GTK~4, FFmpeg и ExifTool средствами пакетного менеджера операционной системы, а затем установить зависимости Python.

Пример установки Python-зависимостей:

\begin{verbatim}
pip install -r requirements.txt
\end{verbatim}

\subsection{Запуск}

Запуск приложения выполняется из каталога проекта:

\begin{verbatim}
python app.py
\end{verbatim}

После запуска открывается окно Floppy с элементами выбора файлов и настройки параметров.

\subsection{Основной сценарий использования}

\begin{enumerate}
	\item нажать кнопку \texttt{Choose files} или перетащить видеофайлы в окно приложения;
	\item выбрать значение качества;
	\item при необходимости указать максимальную высоту видео;
	\item при необходимости указать максимальную частоту кадров;
	\item при необходимости включить \texttt{Copy metadata};
	\item нажать кнопку \texttt{Reencode};
	\item дождаться завершения обработки;
	\item найти рядом с исходным файлом новый файл с суффиксом \texttt{\_compressed}.
\end{enumerate}

\subsection{Типовые ошибки}

Если пользователь нажал \texttt{Reencode}, но не выбрал файлы, программа выводит сообщение \texttt{Choose files first}. В этом случае нужно выбрать хотя бы один видеофайл и повторить запуск.

Если в системе не установлен FFmpeg или отсутствует подходящий HEVC-кодировщик, перекодирование завершится ошибкой. Для решения проблемы нужно установить FFmpeg или использовать сборку FFmpeg с поддержкой HEVC-кодирования.

Если включен режим \texttt{Copy metadata}, но в системе не установлен ExifTool, приложение сообщит об ошибке до запуска перекодирования. В этом случае нужно установить ExifTool или отключить копирование метаданных.

Если выбранный файл поврежден или не является видеофайлом, FFmpeg может завершить обработку с ошибкой. В таком случае следует проверить исходный файл или выбрать другой файл.

\section{Руководство разработчика}

\subsection{Структура проекта}

Проект Floppy расположен в каталоге \texttt{floppy}. Основные файлы:

\begin{itemize}
	\item \texttt{app.py} --- точка входа приложения и описание графического интерфейса;
	\item \texttt{engine.py} --- логика перекодирования одного файла;
	\item \texttt{utils.py} --- работа с FFmpeg, FFprobe, ExifTool, кодировщиками и параметрами вывода;
	\item \texttt{requirements.txt} --- список Python-зависимостей.
\end{itemize}

\subsection{Поток выполнения}

При запуске \texttt{app.py} создается объект \texttt{FloppyApp}, а затем главное окно \texttt{MainWindow}. Пользователь выбирает файлы, после чего обработчик кнопки считывает значения из интерфейса и запускает отдельный поток. В этом потоке для каждого файла вызывается асинхронная функция \texttt{engine.reencode}.

Функция \texttt{reencode} получает технические данные исходного видео через функции из \texttt{utils.py}, формирует параметры FFmpeg и запускает обработку. Если включено копирование метаданных, перед обработкой проверяется наличие ExifTool, а после успешного завершения FFmpeg выполняется перенос тегов в выходной файл. Прогресс передается обратно в интерфейс через callback. Обновление GTK-виджетов выполняется через \texttt{GLib.idle\_add}, чтобы изменения происходили в основном потоке интерфейса.

\subsection{Выбор кодировщика}

Доступные кодировщики описаны в словаре \texttt{ENCODERS}. Порядок выбора задан списком \texttt{ENCODER\_PRIORITIES}. Для добавления нового кодировщика нужно:

\begin{itemize}
	\item добавить описание в \texttt{ENCODERS};
	\item указать имя кодека FFmpeg;
	\item задать параметры качества;
	\item при необходимости указать аппаратное ускорение и дополнительные параметры;
	\item добавить ключ кодировщика в \texttt{ENCODER\_PRIORITIES}.
\end{itemize}

pip install -r requirements.txt
